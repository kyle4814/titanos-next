The final business declaration

TITANOS is a one-person AI engineering practice in Brisbane, run with a team of AI agents and a strict test gate. It builds software, security checks and AI systems for small and mid-sized businesses.

This page is everything in the open: what has been built, what it cost, how fast it ran, how it is tested, how it is kept safe, and how you can do the same. It is free to read, copy and share.

Tests and automated testing

  • 527 automated test suites in the engine's main gate.
  • 149 test commands in this website's test manifest, plus built-page checks that run after every build.
  • 114 test files and 1,054 test cases in the customer backend (sign-in, billing, security).
  • 21 mutation-test scripts that break the code on purpose to prove the tests notice.
  • Every failure that reaches a person becomes a regression test the same day.
  • Copy is linted too: no dashes, no filler words, and no addresses or credentials in anything public.

Security

  • Outside parties are only ever checked passively, from public DNS records. Nothing of theirs is touched.
  • Money, credentials, legal commitments, messages to third parties and anything irreversible need a human approval tap first.
  • Secrets live outside the code and are never pasted into chat; a secret scan is part of the engine's test gate.
  • The website sets a content security policy and publishes a security contact file (security.txt).
  • The customer backend verifies signed payment events, rate limits sensitive routes per visitor, and sends no-store and anti-framing headers on every response.

How we do it

  1. Write down what done means first. Before anything is built, list the acceptance checks: what must work, what must not break, what the limits are. Everything later is judged against that list, not against a feeling.
  2. Run one orchestrator and many small agents. One session holds the plan and the context. It hands self-contained briefs to agents, each with one job, its own branch and the exact files it may touch. Small, bounded jobs fail cheaply.
  3. Tests before claims. A change is not described as working until a test shows it. Each bug that gets through becomes a regression test, and mutation tests confirm the tests really fail when the code is wrong.
  4. Run the full suite on a cloud test runner. The workstation stays free for building. The whole suite runs on a separate machine from a clean copy, and the pass and fail counts are read, not assumed.
  5. Use independent review. A different agent, with no stake in the change, reviews it. It only blocks on a demonstrated fault. Everything else goes on a list for later, so work keeps moving.
  6. Put approval gates around the irreversible. Spending money, handling credentials, signing, messaging a third party and deleting things go to a person as a one-tap card. Everything reversible and in scope just gets done.
  7. Keep receipts. Every change leaves a commit, a test result and a note of what is still unknown. A number without a source and a date does not get published.
  8. Turn repeats into code. Anything done twice becomes a script with a test. That is how a one-person practice keeps pace: the machine does the known, the person decides the unknown.

This is not magic and it is not hands-off. A person sets the direction, approves the gated steps and owns every decision that matters.
