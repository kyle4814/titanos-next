That is the headline. What did the replay find that we did not expect?

1. Public code, every change timestamped

  • This website's source, every change dated to the second: github.com/kyle4814/titanos-next
  • SpoofGuard, our free open-source email security tool: github.com/kyle4814/spoofguard

2. Full test runs, with timestamps

Raw logs, each line stamped with the time it ran (7 October 2026, Brisbane time). No summary written afterwards, just the output:

  • Trading app: 250 of 250 tests passed
  • SpoofGuard: 83 of 83 tests passed

3. The 3.5-hour build, replayed commit by commit

Think of a builder's time-lapse. We checked out every one of the 57 saved versions of the trading app in order and ran its tests. Each line of the replay shows when that version was saved, its ID, and how many tests passed. Tests grew from 20 at 05:41 to 250 at 09:37.

Open the full replay log

Here is the part we did not expect, shown as found: five in-between versions each have one test that fails when replayed today. Those tests depend on the time of day or on live market data (for example, a session-clock label and a live one-tap trade). Every one passes at the final version, 250 of 250.

How the replay was run, so anyone with the repository can repeat it:

for c in $(git rev-list --reverse HEAD); do git checkout -q "$c" echo "$(git log -1 --format=%ci) $(node --test tests/*.test.js | grep '^# pass')" done

What this proves, and what it does not

It proves the base: real code, real tests, real timestamps, and the speed of that build. Our larger figures (the compounding, the second account, the engineer-equivalents) are calculations built on this base, and each is labelled as a model. They become facts only as weekly results confirm them, and we publish those results too.
